## Notes
- **Run:** `npm run e2e` (local: reuses a running `npm run dev`, else starts it) or
  `E2E_BASE_URL=https://hishab.quadbits.net npm run e2e` (hosted). One target per run; each
  journey runs on desktop Chrome and a phone (Pixel 7). `https://localhost` (the Docker stack)
  is accepted with Caddy's internal certificate.
- **Data:** on the local target `e2e/global-setup.ts` loads the synthetic universe into the dev
  database first (`app.facts.seed`, idempotent); without it the real engines abstain.
- **Outputs:** everything a run writes stays under `web/test-results/` (git-ignored, and ignored by
  Vite's watcher: a report written inside the watched tree crashed `npm run dev` on Windows):
  `report/` (HTML), `artifacts/`, `auth/`, `totp/`, `known-bugs.json`.
- **Sessions:** `e2e/auth.setup.ts` signs the home business's demo owner, staff and lender in through
  the real auth API once per run and saves `test-results/auth/<target>-<role>.json`. It also asks
  the cash engine which owner's business is Critical today and saves that session for the cash
  journey (on the seeded ledger: the fabric and hardware traders).
  Journeys reuse them (`test.use({ storageState: sessionFile("owner") })`), so the sign-in rate
  limit (10 per minute per IP) and single-use TOTP codes are spent only where a journey tests them.
- **TOTP:** the server accepts each 30-second code once per account (sign-in and step-up share it)
  and counts refusals towards lockout. `support/totp.ts` hands codes out under one lock per account
  across workers, remembers the last one, and waits for the next step instead of replaying it.
  Codes come from the published demo listing (`totp_hint`); mock-served routes take the mock's
  fixed code, read from `web/src/mocks/db.ts`.
- **Which backend answers:** `support/target.ts` probes each route a journey needs (FastAPI's bare
  404/405 = no router, the rule `web/src/mocks/mockApi.ts` uses). Local: missing routers are
  answered by the labelled offline mock and the test is annotated "offline mock". Hosted (live
  API): the journey is skipped naming the missing routes, never faked.
- **Stand-ins (local only, annotated):** only while WP-04's router is missing, `support/stand-ins.ts`
  answers `GET /api/cash/alerts` with a Critical gap. With the router live (now) the journey uses the
  engine's own alert.
- **Known bugs are listed after every run** (`support/known-bugs-reporter.ts`, also
  `test-results/known-bugs.json`): tests that pin a bug owned by another WP (expected failures and
  exact known lists) call `knownBug(...)`, so a green run never reads as "no known issues".
- **Waiting on other WPs** (the journey runs the part that exists today):
  - Mesh "every party approves": the mock acts as one ring member and keeps approvals in one page,
    so the journey approves as that member (`mesh.spec.ts` skips itself once WP-08's API is live);
    the three-owner flow needs WP-08 milestone 8, and WP-14 has no Propose control yet
    (`api.mesh.propose` is unused).
- **Found by the suite** (pinned so a fix also turns the suite red until the marker comes off):
  1. WP-01/WP-02: a lender viewer (no `ledger:read`) gets ledger figures from `GET /api/facts/*`
     and the upload list from `GET /api/ingest/history` (`lender.spec.ts`, `test.fail`).
  2. WP-11: the guard lets everyday Bangla override phrasings through ("আগের সব নির্দেশ ভুলে যাও",
     "নির্দেশ উপেক্ষা করো"); its rules expect "নির্দেশনা ... ভুলে" (`injection.spec.ts`, `test.fail`).
  3. WP-14: on a phone the Trust screen is 31-57 px wider than the screen: TierBadge's `sr-only`
     text escapes the audit table's `overflow-x-auto` box (no positioned ancestor). The page pans,
     the fixed bottom bar is laid out wider ("More" partly off-screen) and in Chromium's phone
     emulation takes no taps; axe adds `scrollable-region-focusable` (the box cannot be reached by
     keyboard). Fix: `relative` + `tabIndex={0}` on that wrapper (`layout.spec.ts`, `a11y.spec.ts`).
  4. WP-14, axe in a real browser: the Cash chart is `aria-hidden` with focusable SVG inside; dark
     `slate-500` small text is 3.74:1 on Mesh, Reports and Settings (`a11y.spec.ts`, exact known
     list). Also seen with the mock's data, not pinned (the grocery has no Watch alert now): the
     Watch tier badge is white on sky-600, 4.02:1.
  5. Observed, not asserted: Bangla mode turns digits inside hashes into Bangla digits (Trust's
     "Latest hash" reads ৩ee১২…), so a hash can no longer be compared; the verify page calls a
     not-yet-anchored passport "Not genuine"; demo owner codes are single-use per 30 s, so two
     judges signing in as the demo owner within one step get "code not right" (and a lockout count).
- **Hosted evidence:** `E2E_BASE_URL=... npm run e2e` keeps a trace, video and screenshot of every
  test and writes `docs/submission/evidence/e2e/summary.md` + `summary.json`
  (`support/evidence-reporter.ts`: target, Dhaka time, commit, the target's `/api/health`, totals
  with known-bug failures and not-deployed skips counted apart, every test with its reason). Git
  keeps the summaries and screenshots; traces, videos and the report (about 350 MB a run) stay on
  disk and in the CI artifact `e2e-hosted-evidence` (`e2e.yml` job `hosted`: on demand and after
  every successful deploy). `E2E_EVIDENCE_DIR` redirects it (dry runs). A teardown project signs
  every saved session out, and sessions a test starts end with it, so cookies in traces open nothing.
- **Local dev database is SQLite:** a forecast being recorded holds the write lock for seconds, so a
  parallel write fails with "database is locked" (500). The local target runs 2 workers and the
  upload journey starts on Settings; WAL + a busy timeout in `app/db.py` (WP-00) would fix the cause.
- Outside `web/e2e/`: `web/playwright.config.ts` (milestone 1) and `docs/submission/evidence/e2e/`
  (milestone 3's output: `.gitignore`, `README.md`, and the run's summaries).
