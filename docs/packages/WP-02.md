# WP-02 — Ingestion (mobile-money first)

Owner: A1 (PC-1) · Branch: `wp-02-ingest` · Wave 1 · Test quota: 80 · Features: **P4** (pending approval; core CSV import is needed regardless)
Owns: `backend/app/ingest/`, `backend/app/api/ingest.py`, `backend/tests/ingest/`
Depends on: WP-00, WP-01 store.

## Goal
Turn the files a real Dhaka shop actually has into typed facts, with a preview before commit.

## Milestones
1. **Parsers** → contracts `Transaction`/`Invoice`/`Bill`: bKash merchant statement (CSV/XLSX),
   Nagad statement, generic bank CSV, generic ledger CSV/XLSX (column mapping step), the
   synthetic formats from WP-00. Detect format automatically; report unparsed rows with reasons.
2. **Normaliser:** amounts with Bangla digits (০-৯) and "Tk/৳/BDT", Bangla/Banglish month names,
   dd/mm vs mm/dd disambiguation, duplicate detection (same amount+time+ref), counterparty
   clustering into party tokens (privacy hook from WP-03).
3. **Ledger photo OCR (baki khata):** local Tesseract with `ben`+`eng` (no image leaves the server);
   extract name/amount/date lines into *draft* invoices that the owner confirms row by row.
   Confidence per row; low-confidence rows flagged, never auto-committed.
4. **Preview → commit flow** with a keyed digest so the committed file is exactly the previewed one.
5. **API:** `POST /ingest/preview`, `POST /ingest/commit`, `GET /ingest/history`.

## Tests (≥ 80)
One parametrised case per format variant and per malformed-row type; Bangla digit table;
date ambiguity table; dedupe property; preview/commit digest mismatch rejected; OCR on fixture
images (rendered Bangla text) → expected drafts; nothing committed without confirmation.
