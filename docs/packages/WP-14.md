# WP-14 — Frontend

Owner: B1 (PC-2) · Branch: `wp-14-web` · Wave 1–3 · Test quota: 110 (Vitest) · Features: **N13 (UI), P6, P9, P12**, all screens
Owns: `web/src/` (not `web/e2e/`)
Depends on: WP-00 contracts (generate TS types from `docs/api/contracts.json`); mock API until each backend router lands.

## Design
Mobile-first (360 px), calm and trustworthy; big numbers, one primary action per screen.
Self-hosted fonts that cover Bangla and Chinese (e.g. Noto Sans Bengali / Noto Sans SC subsets).
No external CDNs. Light/dark. i18n en/bn/zh with a language switch on every screen.

## Notes
- **API modes** (`web/src/api/apiMode.ts`): `live` (real backend only; production default),
  `mock` (offline mock in `web/src/mocks`, always labelled in the banner), `auto` (development
  default: the real backend first, the mock only for routes whose router has not landed:
  FastAPI's bare `{"detail":"Not Found"}`, 405, or the API not running). Production builds
  follow `VITE_API_MODE` at build time; the mock code is a separate chunk that live builds never load.
- **Shapes the web expects** are typed in `web/src/api/types.ts` (envelopes) and
  `web/src/api/endpoints.ts` (routes); the mock serves exactly these. For WP-11:
  `POST /api/auth/login {email,password}` → `{status:"ok",session}` or `{status:"totp_required"}`;
  `POST /api/auth/login/totp {code}` → `Session`; `GET /api/auth/me` → `Session` (401 signed out);
  `POST /api/auth/logout` → 204; `GET /api/auth/demo-accounts` → `DemoAccount[]` (demo mode only,
  optional `totp_hint` = current demo code). `Session = {principal, display_name, business_name,
  totp_enrolled, data_mode}`. Errors: 401 `error.invalid_credentials`, 401 `error.invalid_code`,
  423 `error.account_locked` with `detail.retry_after_minutes`. A wrong **step-up** code must be
  403 `error.step_up_failed`, not 401 (401 signs the user out). EXECUTE calls send
  `X-Step-Up-Code` and `X-Idempotency-Key` headers.
- Nav visibility per role is a UI convenience (`web/src/navigation.ts`); the API enforces access.
- For WP-15: `/` now requires sign-in, so `web/e2e/smoke.spec.ts` must sign in (demo owner +
  demo code) before expecting the Today heading.
