# WP-01 — Typed Fact Ledger + provenance

Owner: A1 (PC-1) · Branch: `wp-01-facts` · Wave 1 · Test quota: 60 · Features: **N5, N13 (backend)**
Owns: `backend/app/facts/`, `backend/app/api/facts.py`, `backend/tests/facts/`
Depends on: WP-00 contracts.

## Goal
Every number any engine uses or shows is a typed fact with a traceable origin. Clicking a figure
in the UI (WP-14) calls this WP's API to get its formula and source rows.

## Milestones
1. **Store.** Persist Transactions/Invoices/Bills/Obligations and derived `Fact` rows
   (`metric`, `value: Decimal`, `unit`, `period`, `entity_token`, `source_refs[]`, `data_mode`).
   Exact lookup API: `get(metric, period, entity)`; no fuzzy or vector lookup anywhere.
2. **Metric registry.** Named, versioned metric definitions (`net_sales`, `cash_in`, `cash_out`,
   `closing_balance`, `dso`, `dpo`, `gross_margin`, …) each with a `formula_id`, a human-readable
   formula string, and a pure function computing it from typed inputs.
3. **Provenance graph.** Every computed figure records `formula_id` + input fact IDs → source
   row IDs. `explain(figure_id)` returns formula, inputs with values, and source rows (masked
   per caller role via WP-03/WP-11 hooks; stub the masking interface).
4. **API:** `GET /facts/{metric}`, `GET /explain/{figure_id}`.

## Tests (≥ 60)
Exact lookup never returns a near-miss metric; every registry formula against hand-computed
values (parametrised); provenance completeness property (Hypothesis: any computed figure resolves
to ≥ 1 source row); version changes don't rewrite old figures; masking hook is always called.
