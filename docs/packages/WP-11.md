# WP-11 — Security, permission tiers, audit, injection guard

Owner: B2 (PC-2, second terminal) · Branch: `wp-11-security` · Wave 1–2 · Test quota: 110 · Features: **P2, P5**
Owns: `backend/app/security/`, `backend/app/api/auth.py`, `backend/tests/security/`
Depends on: WP-00.

## Milestones
1. **Auth:** email + password (argon2) + TOTP step-up; sessions as HttpOnly SameSite=Strict
   cookies; lockout; demo accounts only in demo mode (off in production).
2. **Roles:** owner, accountant, staff, lender_viewer (consented, scoped, expiring), compliance.
3. **Permission tiers:** READ, SUGGEST, DRAFT, EXECUTE, DENY per action type; policy table in
   one file; EXECUTE needs owner approval + fresh TOTP; approvals expire in 24 h; idempotency keys;
   re-check policy at execution. DENY list: change bank details, add payees, disable audit,
   export raw PII.
4. **Audit chain:** append-only, SHA-256 hash-chained, persisted in the DB (no UPDATE/DELETE),
   verify endpoint; daily head anchored via WP-08's chain module.
5. **Injection guard:** rules layer + classifier from WP-17 (multilingual: EN, BN, Banglish, ZH);
   runs on every user message, uploaded text and tool output before the LLM sees it; quarantines
   hits; logs to audit.
6. **Web hardening:** CSP, HSTS, strict CORS, rate limits per route, security headers test.
7. **Security self-assessment draft** `docs/submission/security-self-assessment.md`: tier table,
   threat model (STRIDE), OWASP LLM Top 10 mapping, known-risk list (honest).

## Tests (≥ 110)
Tier matrix (every role × action, parametrised); approval expiry/idempotency/replay; TOTP
window; lockout; audit tamper detection (edit, delete, reorder); guard catches the adversarial
fixture set; headers present; CORS rejects foreign origin; rate limit triggers.
