# WP-11 — Security, permission tiers, audit, injection guard

Owner: B2 (PC-2, second terminal) · Branch: `wp-11-security` · Wave 1–2 · Test quota: 110 · Features: **P2, P5**
Owns: `backend/app/security/` (incl. `app_hooks.py`), `backend/app/api/auth.py`, `backend/tests/security/`,
`docs/submission/security-self-assessment.md` (draft; WP-19 finalises it with the orchestrator)
Depends on: WP-00.

## Milestones
1. **Auth:** email + password (argon2) + TOTP step-up; sessions as HttpOnly SameSite=Strict
   cookies; lockout; demo accounts only in demo mode (off in production).
2. **Roles:** owner, accountant, staff, lender_viewer (consented, scoped, expiring), compliance.
3. **Permission tiers:** READ, SUGGEST, DRAFT, EXECUTE, DENY per action type; policy table in
   one file; EXECUTE needs owner approval + fresh TOTP; approvals expire in 24 h; idempotency keys;
   re-check policy at execution. DENY list: change bank details, add payees, disable audit,
   export raw PII.
4. **Audit chain:** append-only, SHA-256 hash-chained, persisted in the DB (no UPDATE/DELETE),
   verify endpoint; daily head anchored via WP-08's chain module.
5. **Injection guard:** rules layer + classifier from WP-17 (multilingual: EN, BN, Banglish, ZH);
   runs on every user message, uploaded text and tool output before the LLM sees it; quarantines
   hits; logs to audit.
6. **Web hardening:** CSP, HSTS, strict CORS, rate limits per route, security headers test.
   *How (no `main.py` edit needed):* put middleware, exception handlers and startup checks in
   `backend/app/security/app_hooks.py` → `def install(app, settings)`. `create_app` calls it after
   every router is mounted and before CORS, so CORS wraps your 429/403 responses too.
   `from app.main import api_routes` lists every route (path, methods, endpoint) if you want
   startup to fail when a route has no tier. CORS itself is already strict in `main.py` (origins
   from `CORS_ORIGINS`, fixed methods and headers): prove it with tests; a change → Question.
   Caddy (`infra/Caddyfile`, WP-18) already sends HSTS, CSP, X-Frame-Options, Referrer-Policy and
   Permissions-Policy for the site; add the API-relevant ones in your hook too, so a request
   that bypasses Caddy (tests, direct port) is covered. A Caddy change → Question.
7. **Security self-assessment draft** `docs/submission/security-self-assessment.md`: tier table,
   threat model (STRIDE), OWASP LLM Top 10 mapping, known-risk list (honest).

## Interfaces for other WPs
- Signed-in user: `from app.security.deps import current_principal` →
  `principal: Principal = Depends(current_principal)` (401 `error.not_authenticated` otherwise).
  WP-01: this replaces the `caller_role` stub and the `tenant_id` query parameter in `app/api/facts.py`.
- Permissions: `Depends(require(Permission.audit_read))` (403 otherwise); table in
  `app/security/roles.py`. Fresh TOTP: `step: StepUp = Depends(step_up)` then
  `if step.problem: return step.problem.response()` (reads `X-Step-Up-Code`; never raises, so
  failed codes still count towards the lockout).
- EXECUTE actions (WP-08, WP-10, WP-12): `POST /api/approvals {card}` + `X-Idempotency-Key`,
  owner approves with `X-Step-Up-Code`, then `POST /api/approvals/{id}/execute`. Plug in the
  real effect with `app.security.approvals.register_executor(ActionType.x, fn)`; without one,
  an executed action is recorded only. Tier per role/action: `app.security.policy.decide()`.
- Audit: `AuditLog(db).append(tenant, actor=..., action=..., now=..., tier=..., target=...,
  details={...})` — details are ids/counts/digests only, never personal data. The daily anchor
  job is `security.anchor_audit_heads` (worker); WP-08's anchorer does the chain write.
- Injection guard (WP-10 gateway/agents, WP-02 ingest): `screen(db, tenant, actor, text,
  Source.user_message | uploaded_text | tool_output, now)` before any model sees the text; a
  verdict with `allowed=False` is already quarantined and audited. WP-17: install the model with
  `guard.set_classifier(guard.load_classifier(model_dir))` (needs `onnxruntime` + `tokenizers`).
- Source-row masking for WP-01: `app.security.roles.policy_masker(tenant, rows, caller)`
  shows rows only to a same-tenant caller holding `source_rows:read` (expiry honoured); the
  app hook installs it and a stable `set_masking_key` derived from `SECRET_KEY`.
- Errors as `ApiError` bodies from dependencies: declare routers with
  `APIRouter(route_class=app.security.errors.ProblemRoute)`.
- Web (WP-14): `/api/auth/*` matches `web/src/api/types.ts` (Session, LoginResponse, DemoAccount).
