# WP-06 — Financing-option matching

Owner: Orchestrator · Branch: `wp-06-financing` · Wave 2 · Test quota: 90 · Features: **P1, N20, P14**
Owns: `backend/app/engines/financing/`, `data/public/financing/`, `backend/app/api/financing.py`, `backend/tests/financing/`
Depends on: WP-01, WP-04 (gap size and timing), WP-08 (mesh lender records).

## Goal
For a given need (amount, date, duration), rank every realistic option — loans and non-loan —
by true cost and fit, with reasons.

## Milestones
1. **Catalogue** `data/public/financing/bd.yaml`: real Bangladesh options (bank SME/CMSME loans,
   Bangladesh Bank refinance-backed products, bKash–City Bank and BRAC–bKash nano loans,
   factoring/invoice discounting, leasing, MFI loans) with published rates/fees, limits, tenor,
   eligibility, and **source URL + checked-on date** per row. Non-loan options are generated:
   buyer early pay (WP-05), supplier term extension, mesh netting (WP-08), owner top-up.
   P14: optional `cn.yaml` modelled on WeBank/MYbank-style digital SME credit, labelled "modelled".
2. **Effective annual cost engine:** APR including fees, processing charges, compulsory
   deposits, flat-vs-reducing rates, daily-debit structures; true cost in Tk for the exact need.
3. **Eligibility rules** with reasons: pass / fail / "not on record" (never invent a fact).
4. **Fit:** repayment schedule vs WP-04 forecast → P(breaching buffer) for each option.
5. **Ranking:** cost, fit, speed, approval likelihood (heuristic, explained), lender track record (N20).
6. **Lender check (N20):** LenderProfile from mesh events (quoted vs realised cost, speed,
   hidden fees, disputes) + licence status; cold-start seed from public sources; synthetic history labelled.
7. **Application pack draft:** pre-filled from facts, as an ActionCard (EXECUTE tier = owner approval).
8. **API:** `POST /financing/match`, `GET /financing/lenders/{id}`.

## Tests (≥ 90)
APR table vs hand calculations (flat vs reducing, fees, daily debit); one eligibility case per
rule; "not on record" never passes; ranking stability on irrelevant noise (N16 hook); fit uses
the forecast; every product row has a source URL; lender score monotonic in hidden-fee rate.

## Questions
- **Application cards cannot be approved (WP-06 x WP-11, needs a decision).** `draft_application`
  returns an EXECUTE card (submitting an application commits the business, CLAUDE.md rule 4),
  but `app/security/policy.py` gives every role at most DRAFT on `draft_loan_application`, so
  `policy.decide(owner, draft_loan_application, EXECUTE)` answers `policy.tier_too_low`: the
  owner can request approval but never approve it. Proposed fix: a new `ActionType`
  `submit_loan_application` (contract, WP-00), REQUIRED EXECUTE with owner E / accountant D in
  the WP-11 policy table, and the WP-06 card switched to it; `draft_loan_application` stays the
  DRAFT step the API already checks. Alternative: lower the card to DRAFT and let the owner hand
  the pack to the lender outside Hishab.
- **Lender licence registry.** `GET /financing/lenders/{id}` reports `licence_status: unknown`
  for every lender: no Bangladesh Bank / MRA licence list with source URLs is loaded yet.
  Cold start still scores 60; with a track record, "unknown" costs 15 points.
