# WP-03 — Privacy: detectors, token vault, anonymiser

Owner: Orchestrator (moved from B2 on 18 Oct) · Branch: `wp-03-privacy` · Wave 1 · Test quota: 70 · Features: **N6, N18, P11**
Owns: `backend/app/privacy/`, `backend/tests/privacy/`
Depends on: WP-00.

## Goal
No raw personal or business-identifying data ever reaches an external model or a log line.

## Milestones
1. **Detectors** (deterministic first): Bangladesh mobile numbers (+880 / 01XXXXXXXXX), NID
   (10/13/17 digits), bKash/Nagad numbers, bank account and card numbers, emails, addresses
   (Dhaka area names list), person and shop names (from the party registry + a name list).
2. **Token vault:** `PERSON_xxxxx`, `SHOP_xxxxx`, `PHONE_xxxxx` = HMAC(tenant, value); originals
   encrypted with AES-256-GCM (key from env, never logged); restore only via an authorised call
   with a role check hook (WP-11).
3. **Anonymiser for LLM payloads:** replace tokens with neutral labels ("Firm A", "Customer 3"),
   shift dates to relative ("month t-2"), strip places and rare product names that could
   re-identify (memorisation guard, N15), optional secret amount scaling (P11: ratios survive,
   scale hidden; fixed thresholds stay in code). Returns a mapping to restore the answer.
4. **Fail-closed gate:** `assert_safe(payload)` raises if any detector fires; the LLM gateway
   (WP-10) must call it on every request.

## Tests (≥ 70)
Parametrised detector tables (positives and look-alike negatives); round-trip property
(anonymise → restore = original); scaling preserves ratios property; gate blocks every detector
class; vault ciphertext never contains plaintext; wrong key fails closed; logs contain no PII.
